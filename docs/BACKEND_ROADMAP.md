## ۲. ساختار کلاینت‌های احراز هویت پیاده‌سازی شده

- `src/lib/supabase/client.ts`: کلاینت مرورگر بر پایه `createBrowserClient`
- `src/lib/supabase/server.ts`: کلاینت سرور بر پایه `createServerClient` و کوکی‌های استاندارد Next.js
- `src/lib/supabase/middleware.ts`: مدیریت نوسازی نشست‌ها و اعتبارسنجی توکن با `getUser()`
- `src/proxy.ts`: محافظت خودکار از مسیرهای محرمانه `/app/*` بر اساس معماری نوین Next.js 16
- `src/app/auth/callback/route.ts`: تبادل امن کد یک‌بارمصرف تایید ایمیل با نشست دائمی
- `supabase/migrations/20261107000000_init_auth_and_profiles.sql`: ایجاد خودکار جدول پروفایل، فضای کاری شخصی و عضویت پیش‌فرض بلافاصله پس از ثبت‌نام

```env
NEXT_PUBLIC_SUPABASE_ANON_KEY=eyJ...

# کلید محرمانه ادمین سمت سرور (هرگز در کلاینت استفاده نمی‌شود)
SUPABASE_SERVICE_ROLE_KEY=eyJ...

# نشانی دامنه برای ریدایرکت‌های Auth و Callback
NEXT_PUBLIC_SITE_URL=http://localhost:3000
```

## ۴. اصول استقلال زیرساخت و مهاجرت‌پذیری (Self-Hosting Checklist)

1. **مدیریت ۱۰۰٪ با فایل‌های Migration:** تمام جداول و توابع باید در پوشه `supabase/migrations/` نگهداری و کامیت شوند.
2. **عدم وابستگی به ویژگی‌های انحصاری هاست:** پرهیز از کدهای خاص Edge ورسل و پایبندی به استانداردهای Node.js و Web API.
3. **امنیت در سطح سطر (RLS):** تمامی جداول تحت حفاظت کامل RLS هستند تا حتی در صورت تغییر کلاینت، دسترسی غیرمجاز ناممکن باشد.
4. **تست بازنشانی لوکال:** قابلیت ریست و بازسازی کل دیتابیس با داکر بدون اتکا به پنل ابری.
